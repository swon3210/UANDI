## 역할

문의 한 건에 대한 **1:1 답장 이메일**을 만든다. 글은 Claude가 쓰고, 초안은 Gmail 임시보관함에 올리며,
**보내기는 유저가 누르거나 유저가 채팅에서 "보내줘"라고 명시했을 때만** Claude가 누른다.
푸시가 아니라 이메일인 이유: 문의가 이메일 회신처를 남기고 들어오고, 탈퇴·오류처럼 길고 민감한 안내는 잠금화면 푸시와 맞지 않으며,
반쪽 삭제된 계정처럼 FCM 토큰이 없는 사용자에겐 푸시가 닿지 않는다.

## 입력

`$ARGUMENTS` — 피드백 id(`/feedback`가 보여준 id) 또는 비어 있음. 비어 있으면 어떤 건인지 먼저 묻는다.

## 실행 순서

1. **문의 읽기** — `node scripts/list-feedback.mjs --id <feedbackId>`로 원문·회신 이메일(`contactEmail`)·플랫폼·앱 버전을 확인한다.
   받는사람은 이 `contactEmail`이다. 없으면 `author.email`을 쓰되 유저에게 알린다.
2. **사실 확인** — 답장에 쓸 내용이 지금 사실인지 확인한다.
   - 원인을 코드에서 찾았는가(추측이면 추측이라고 쓴다).
   - "고쳤다"고 쓰려면 **프로덕션에 배포돼 있어야** 한다(`gh api repos/swon3210/UANDI/commits/<sha>/status`의 `Vercel – uandi-web`이 success).
     배포 전이면 "고치는 중이고 언제 올라간다"로 쓴다.
   - 상대가 해야 할 경로는 실제 화면 이름과 순서로 적는다(필요하면 E2E 캡처로 확인).
3. **본문 쓰기** — `.claude/skills/reply-feedback/template.html`을 스크랩패드로 복사해 `[[ ]]`를 채운다.
   완성 예시는 같은 폴더의 `example-account-deletion.html`(탈퇴 실패 문의 답장). 목소리 규칙은 아래.
4. **미리보기** — 배포 전 이미지도 보이도록 로컬 파일을 인라인해 캡처한다.
   ```bash
   node scripts/feedback-reply-email.mjs preview <reply.html>
   ```
   캡처 PNG를 `SendUserFile`로 보여주고 문장 수정을 받는다. 본문이 확정될 때까지 Gmail에 올리지 않는다.
5. **Gmail 초안** — 유저가 본문을 승인하면 임시보관함에 올린다. 스크립트가 본문 이미지 URL이 모두 200인지 먼저 확인한다.
   ```bash
   node scripts/feedback-reply-email.mjs draft <reply.html> --to <contactEmail> --subject "[말랑 가계부] <한 줄 제목>"
   ```
   ego lite에 운영 Gmail(swon3210@gmail.com)이 로그인돼 있어야 한다. 로그인 화면이면 스크립트가 `handOff()`하고 멈추니 유저에게 로그인을 부탁한다.
   출력의 `imgs[].loaded`가 전부 `true`인지 보고, 캡처를 유저에게 보여준다.
6. **발송** — 유저가 직접 보내는 것이 기본. 유저가 채팅에서 "보내줘"라고 하면 그때만 ego-browser로 같은 TaskSpace(`말랑 문의 답장 메일`)의 초안에서 보내기를 누른다.
   보낸 뒤 보낸편지함에서 확인하고 `task.finish({ keep: [] })`로 닫는다.
7. **뒷정리** — 피드백 상태(확인함/해결)는 유저가 어드민(`/admin` 피드백 탭)에서 바꾼다. 스크립트에 쓰기 기능을 넣지 않는다.

## 목소리 규칙

- **"말랑 가계부를 만들고 있는 부부입니다"로 시작, "말랑 부부 드림"으로 끝낸다.** 1인칭은 "저희". 고객센터가 아니라 만든 사람이 쓰는 편지다.
- 첫 줄에 **어떤 글에 대한 답인지** 원문을 짧게 인용한다("탈퇴가 되지 않는다"고 남겨 주신 글…).
- 사과는 상대가 겪었을 일을 구체적으로 적는다. "불편을 드려 죄송합니다" 한 줄로 끝내지 않는다.
- 원인은 **쉬운 말 한두 문장**. 기술 용어(토큰, WebView, 재인증) 대신 상대가 본 현상으로 설명한다. 저희 실수면 그렇게 쓴다.
- 상대가 할 일은 화살표(→) 경로로, 화면 이름은 앱에 보이는 그대로. 상황이 갈리면 "A 화면이 뜨면 / B 화면이 뜨면"으로 나눈다.
- 마무리는 고마움 한 줄 + 덕분에 무엇이 좋아졌는지. 떠나는 사용자(탈퇴)에게도 똑같이.
- 안 한 것을 했다고 쓰지 않는다. 약속은 날짜나 조건을 붙여서만 한다.
- 이모티콘은 **2개, 많아야 3개**. 인사 옆 하나, 본론 옆 하나. 서명은 이모티콘이 아니라 **마스코트 + 로고 + 태그라인**(고정, 템플릿 6번 블록).

## 이미지 규칙

- 이메일에는 `https://uandi-web.vercel.app/brand/...` 공개 URL만 쓴다. 정적 파일은 앱 전용 게이트를 통과한다. SVG는 이메일에서 안 보이니 PNG만.
- 새 이미지가 필요하면 `apps/web/public/brand/`에 PR로 넣고 **배포가 끝난 뒤** 초안을 만든다. 배포 전에 초안을 만들면 Gmail이 404를 캐시해 이미지가 계속 깨져 보인다(`draft`가 HEAD 200을 확인하는 이유).

## 주의

- 받는사람 이메일·문의 원문은 개인정보다. 답장 HTML을 repo에 커밋하지 않는다(예시 파일에는 이메일을 넣지 않는다). 스크랩패드에서만 다룬다.
- 보내기 버튼은 유저의 명시적 요청 없이는 절대 누르지 않는다. 승인은 매 건마다 새로 받는다.
- 한 문의에 TaskSpace 하나(`말랑 문의 답장 메일`)를 재사용한다. 막히면 새 스페이스를 만들지 말고 유저에게 넘긴다.
