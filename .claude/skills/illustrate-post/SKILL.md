## 역할

이미 써둔 글에서 **그림이 있어야 이해가 빨라지는 지점**을 찾아, 기존 블로그 다이어그램과
같은 결의 SVG를 그려 본문 문단 사이에 넣는다.

**본문 문장은 고치지 않는다.** 글은 글쓴이의 것이고, 이 스킬은 그림만 얹는다.

## 입력

`$ARGUMENTS` — 글 파일 경로 (예: `content/posts/2026-09-13-why-i-write-blog-again.md`)

경로가 없으면 `content/posts/`의 목록을 보여주고 고르게 한다.

---

## 실행 순서

### 1단계: 기준 읽기

아래를 모두 읽는다 (병렬로).

- `$ARGUMENTS` (대상 글)
- `content/blog-config.md` — 글의 목소리. 그림도 이 톤을 벗어나면 안 된다.
- `apps/blog/public/diagrams/fde-cycle.svg`, `fde-two-models.svg`, `fde-timeline.svg`
  — **새 그림은 이 셋과 한 세트로 보여야 한다.** 팔레트·폰트·여백을 여기서 가져온다.

### 2단계: 후보 고르기

글 전체를 읽고 그림이 **이해를 돕는** 지점을 3~5곳 고른다.

**그림이 필요한 곳**

| 신호                               | 알맞은 그림     |
| ---------------------------------- | --------------- |
| 요소 3개 이상의 흐름·순환·분기     | 순서도 / 순환도 |
| "예전엔 이랬는데 지금은 이렇다"    | 좌우 비교       |
| 시간에 따라 벌어진 일              | 타임라인        |
| 무엇이 무엇 위에 얹혀 있는지       | 구조도 / 계층도 |
| 숫자 두세 개의 대비 (30분 vs 이틀) | 막대·비율 비교  |

**그림이 필요 없는 곳 — 고르지 말 것**

- 한 문장으로 충분한 내용 (그림이 문장을 반복하면 독자는 두 번 읽는다)
- 코드 블록이 이미 보여주는 것
- 분위기·장식용 (이 블로그는 삽화로 호흡을 주는 톤이 아니다)
- 글의 척추(핵심 깨달음)를 그림이 대신 말해버리는 자리 — 그건 문장의 몫이다

### 3단계: 보고 후 승인 받기 (그리기 전)

고른 후보를 이렇게 보고하고 **승인을 기다린다. 승인 전에 SVG를 만들지 않는다.**

```
### 후보 1 — 「검증 게이트를 박은 뒤의 작업 순서」
위치: "순서 없이 던지던 시절" 다음 문단 뒤
근거(본문 인용): "기획·디자인·구현 사이사이에 내가 승인할 게이트를 박고 나서야…"
그림: 6단계 순환도 (기존 fde-cycle.svg와 같은 형태)
왜: 단계가 6개라 문장으로 읽으면 순서가 머리에 안 남는다
```

글쓴이가 고른 것만 다음 단계로 간다.

### 4단계: SVG 그리기

각 그림을 `apps/blog/public/diagrams/<글 slug>-<짧은 키워드>.svg`로 저장한다.
(예: `why-i-write-blog-again-loop.svg`)

**치수**

- `viewBox="0 0 680 <높이>"` — 폭 680 고정. 본문 단(max-w-3xl)에 꼭 맞는 크기다.
- 높이는 내용에 맞게 (대개 200~280). 빈 공간을 남기지 않는다.
- `width`/`height` 속성은 쓰지 않는다 (본문 폭에 맞춰 늘어나야 한다).

**팔레트** — 기존 셋에서 그대로 가져온 값만 쓴다. 새 색을 들이지 않는다.

| 쓰임        | 값                                                  |
| ----------- | --------------------------------------------------- |
| 면 배경     | `#ffffff`                                           |
| 중립 테두리 | `#d1d5db` / 화살표·보조선 `#9ca3af`                 |
| 옅은 면     | `#e5e7eb`                                           |
| 본문 글자   | `#1f2328` (제목) / `#374151` / `#6b7280` (보조)     |
| 강조 테두리 | `#e8837a` (브랜드 코럴), 연하게 `#eeb3ac`           |
| 강조 글자   | `#b4544a` (흰 배경에서 코럴은 글자로 쓰기엔 흐리다) |

**강조는 한 곳에만.** 코럴은 "이 그림에서 봐야 할 하나"에만 쓰고 나머지는 회색으로 둔다.

**글자**

```
font-family="Pretendard, 'Pretendard Variable', -apple-system, 'Apple SD Gothic Neo', sans-serif"
```

- 루트 `<svg>`에 한 번만 선언한다.
- 크기: 제목 14~15, 라벨 12~13. 11 이하로 내려가면 본문에서 안 읽힌다.
- 블로그는 라이트 테마 전용이다. **모든 도형에 `fill`을 명시**하고 투명 배경에 기대지 않는다.

**접근성**

- 루트에 `role="img"`와 `aria-label="<그림이 말하는 결론 한 문장>"`
- 화살표는 `<marker>`로 정의해 재사용한다 (기존 파일의 `cGray`/`cCoral` 패턴).

### 5단계: 본문에 넣기

- 위치는 **문단 사이**. 개념을 설명한 문단 **바로 뒤**에 넣는다. 문단 중간을 쪼개지 않는다.
- 형식: `![<alt>](/diagrams/<파일명>.svg)`
- **alt는 그림이 말하는 결론을 한 문장으로** 쓴다. "다이어그램", "그림 1" 같은 말은 쓰지 않는다.
  기존 글의 alt가 기준이다: "기존 방식은 모델만 건네고 조립을 고객에게 맡겨 방치로 끝나고,
  FDE 방식은 엔지니어가 함께 가서 조립하고 성과 숫자까지 책임진다"
- 앞뒤에 빈 줄을 둔다.

### 6단계: 확인

1. 글이 참조하는 그림 파일이 전부 존재하는지 확인한다.

   ```bash
   grep -o '](/diagrams/[^)]*)' "$ARGUMENTS" | sed 's|](/|apps/blog/public/|;s|)||' | xargs -I{} test -f {} && echo "이미지 경로 OK"
   ```

2. 개발 서버가 떠 있으면 글 페이지를 열어 그림이 잘리거나 글자가 겹치지 않는지 본다.
   (`pnpm --filter blog dev` → `http://localhost:3002/posts/<slug>`)

3. 무엇을 어디에 넣었는지 한 줄씩 보고한다.

## 절대 하지 말 것

- 본문 문장 수정·재배열 (그림만 넣는다)
- 승인 없이 SVG 생성
- 장식용 그림 — 이해를 돕지 못하면 넣지 않는다. 후보가 하나도 없으면 "없다"고 보고한다
- 문장을 그대로 도형에 옮겨 적기 (독자가 같은 말을 두 번 읽는다)
- 팔레트 밖의 색, PNG·JPG 생성, 외부 이미지 URL 링크
- `width`/`height` 고정 (본문 폭에서 잘린다)
