## 역할

프로덕션 Firestore `feedback` 컬렉션(어드민 페이지 `/admin`과 같은 데이터)을
**읽기 전용**으로 조회해 유저에게 정리해 보고한다. 데이터를 쓰거나 상태를 바꾸지 않는다.
상태 변경(확인함/해결)은 유저가 어드민 페이지에서 직접 한다.

## 입력

`$ARGUMENTS` — 스크립트에 그대로 넘기는 옵션. 비어 있으면 미확인(new) 건만 조회한다.

| 옵션                              | 뜻                                             |
| --------------------------------- | ---------------------------------------------- |
| (없음)                            | 미확인(new) 최신순 20건                        |
| `--all`                           | 상태 무관 전체                                 |
| `--status new\|checked\|resolved` | 상태 필터                                      |
| `--type bug\|idea\|other`         | 종류 필터                                      |
| `--limit N`                       | 건수(1~200)                                    |
| `--id <feedbackId>`               | 한 건 상세(coupleId·UA·스크린샷 서명 URL 포함) |

## 실행 순서

1. 스크립트 실행 (repo 루트에서):
   ```bash
   node scripts/list-feedback.mjs $ARGUMENTS
   ```
   인증은 `apps/web/.env.local`의 `FIREBASE_SERVICE_ACCOUNT_KEY`를 쓴다.
   워크트리에서 `.env.local`이 없다는 오류가 나면 먼저 `sh scripts/setup-env.sh`를 실행한다.
2. 출력을 아래 형식으로 요약한다. 스크립트 원문을 그대로 붙이지 않는다.

## 보고 형식

- 첫 줄에 **미확인 건수**를 말한다. 0건이면 그렇게 말하고 끝낸다.
- 건마다 번호를 붙이고 다음을 한 묶음으로 쓴다.
  - 제목 줄: 종류(버그/아이디어/기타)와 한 줄 요지. 유저가 "기타"로 보냈어도 내용이 버그 신고면 그렇게 적어 준다.
  - 작성자 이름과 이메일, 작성 시각(KST)
  - 내용은 원문 그대로 인용한다. 줄바꿈도 유지한다.
  - 환경: 플랫폼, 앱 버전(커밋 해시), 직전 경로, 뷰포트. 스크린샷이 있으면 있다고만 적는다.
- 이미 처리된(확인함/해결) 건은 `--all`일 때만 뒤에 따로 짧게 묶는다.
- 마지막에 **코드와 연결되는 단서**가 있으면 한두 줄 덧붙인다. 예: 앱 버전 해시가 어느 커밋인지(`git log -1 <hash>`), 건의한 기능이 이미 있는지 등. 추측이면 추측이라고 쓴다.
- 해결 방법을 묻지 않았으면 바로 수정에 들어가지 않는다. 조사·수정은 유저가 고른 뒤에 한다.

## 주의

- 개인 식별 정보(이메일)가 포함된다. 요약은 유저에게만 보고하고 커밋·블로그·외부 문서에 넣지 않는다.
- 스크립트를 수정할 때도 쓰기(update/delete) 기능은 추가하지 않는다.
