# 어드민 — 사용자 현황 (`/admin`)

운영자가 가입자별로 누가 어떻게 쓰고 있는지 한 화면에서 본다.
GA4(`docs/09-analytics.md`)에는 이메일·이름을 보낼 수 없으므로, 이름·이메일과 함께 보는 표는 Firebase 데이터(Auth + Firestore)로 만든다.

## 접근 제어

- **허용 이메일 목록 = 서버 환경변수 `ADMIN_EMAILS`** (쉼표 구분, 대소문자 무시). 공개 저장소라 이메일을 코드에 적지 않는다.
- 서버(`/api/admin/users`)가 ID 토큰을 검증하고, 토큰의 `email`이 목록에 있고 `email_verified`일 때만 데이터를 준다.
  (에뮬레이터 모드에서는 이메일/비밀번호 테스트 계정이라 `email_verified` 검사를 생략)
- 권한이 없으면 「접근 권한이 없어요」와 「다른 계정으로 로그인」만 보여준다(데이터 요청 결과 403).
- 커뮤니티 모더레이션의 `admins/{uid}`와는 별개다.

## 도메인

- **어드민 전용 도메인 = `NEXT_PUBLIC_ADMIN_HOST`** (프로덕션: `uandi-admin.vercel.app`, `uandi-web` 프로젝트에 붙인 별칭).
  - 그 도메인의 `/`는 `/admin`으로 rewrite, 다른 경로는 `/`로 보낸다(정적 파일·`/__/auth` 프록시 제외).
    로그인은 어드민 화면이 직접 받으므로 로그인 쿠키 검사를 하지 않는다.
  - 다른 도메인(서비스 도메인)에서는 어드민이 없는 것처럼 동작한다: `/admin` 화면은 404,
    `/api/admin/*`도 404(`verifyAdminEmail`이 Host 헤더로 검사). 어드민 도메인을 알려 주지 않는다.
  - 어드민 도메인에서는 GA4 수집을 끈다(운영자 사용이 서비스 통계에 섞이지 않도록).
  - Google 로그인을 위해 Firebase Auth 승인 도메인에 등록돼 있어야 한다.
- 값이 없으면(로컬·E2E) 어느 도메인에서나 `/admin`으로 접근하고, 미들웨어는 로그인 쿠키가 없으면 `/`로 보낸다.

## 화면

- 헤더: 「말랑 가계부 어드민」, 우측 새로고침·로그아웃
- 비로그인: 「운영자 로그인」 + Google 로그인 버튼
- 요약 카드 4개: 전체 가입자 / 커플 연결 / 기록 1건 이상 / 최근 7일 활동
- 검색: 이름·이메일·커플 상대 이메일 부분 일치(대소문자 무시), 결과 수 표시
- 사용자 표: 사용자·가입일·최근 활동·기록·마지막 기록 머리글로 정렬(다시 누르면 방향 전환, 값 없는 행은 항상 뒤).
  기본은 최근 활동 최신순

| 열          | 출처                                                                    |
| ----------- | ----------------------------------------------------------------------- |
| 사용자      | 프로필 사진·이름은 `users/{uid}` 문서 우선(없으면 Auth), `email`은 Auth |
| 가입일      | Auth `metadata.creationTime`                                            |
| 최근 활동   | Auth `metadata.lastRefreshTime` (없으면 `lastSignInTime`)               |
| 커플        | `users/{uid}.coupleId`의 다른 멤버 이메일, 없으면 「미연결」            |
| 기록        | 본인 작성 내역 수 / 커플 전체 내역 수 (`count()` 집계)                  |
| 마지막 기록 | 커플 `cashbookEntries`의 최신 `createdAt`                               |
| 플랫폼      | 써 본 플랫폼 전부(최근 사용 순) — 아래 참고                             |

- 금액·메모·카테고리 같은 가계부 내용은 보여주지 않는다. 건수만.

### 플랫폼 기록

- 로그인 상태로 앱을 열면 `ClientPlatformTracker`가 `users/{uid}.clientPlatforms.{web|android|ios}`에
  마지막 사용 시각을 남긴다. 같은 기기·플랫폼에서는 하루 한 번만 쓴다(localStorage 표식). 어드민 도메인 방문은 기록하지 않는다.
- 판별은 `getClientPlatform()`(네이티브 브리지 → RN WebView → Android WebView UA → web).
- 표에는 기록된 플랫폼을 모두 배지로 보여준다(예: 「Android」「웹」). 배지에 마우스를 올리면 마지막 사용 시각.
- 기록 도입 전 사용자는 푸시 토큰(`users/{uid}/fcmTokens`)의 `platform`으로 보완한다(시각 없음).
  둘 다 없으면 `-`.

## 비용

- 사용자 N명 기준: Auth `listUsers` 1회, `users` 문서 일괄 조회 1회, 사용자별 `count()` 1회 + fcmTokens 조회 1회,
  커플별 `count()` 1회 + 최신 1건 조회 1회. `count()`는 1,000건당 1회 읽기로 과금된다.
- 화면을 열 때만 조회하고 자동 갱신하지 않는다.

## 테스트 (`e2e/specs/admin-users.spec.ts`)

- 허용 목록에 없는 사용자는 「접근 권한이 없어요」를 본다.
- 허용된 계정은 다른 사용자의 이메일·이름·프로필 사진·기록 건수가 담긴 행을 본다.
- 기록 순 정렬, 이메일 검색(일치 1명 / 일치 없음).
- 어드민 도메인 라우팅은 E2E 대상이 아니다(로컬엔 `NEXT_PUBLIC_ADMIN_HOST`가 없음) — 배포 후 프로덕션에서 확인한다.
