# 페이지 명세: 온보딩 (/onboarding)

## 목적

최초 로그인 후 커플 연결이 완료되지 않은 사용자를 안내하는 페이지.
혼자 먼저 시작할 수도 있고, 상대가 합류하는 순간을 함께 축하한 뒤 서비스로 들어간다.

---

## 사용자 스토리

- 신규 사용자로서, 내가 "처음 시작하는 사람"인지 "초대받은 사람"인지 헷갈리지 않고 고르고 싶다.
- 공간을 만든 사용자로서, 초대 코드(또는 링크)를 보내 놓고 상대를 기다리지 않고 **먼저 둘러보고** 싶다.
- 공간을 만든 사용자로서, 코드 대신 **링크 하나**로 초대하고 싶다.
- 초대받은 사용자로서, 코드를 치면 **누구의 초대인지** 확인하고 연결하고 싶다.
- 초대받은 사용자로서, 링크를 눌러 로그인만 하면 코드 입력 없이 바로 연결되길 바란다.
- 두 사람 모두, 연결되는 순간을 **한 화면으로 확인**하고 나서 서비스에 들어가고 싶다.

---

## UI 구성

### 단계 1 — 선택 화면

```
┌─────────────────────────┐
│                         │
│   [말랑 로고]            │
│   함께 모아가는 즐거움     │
│                         │
│  ┌───────────────────┐  │
│  │ 🏠 처음 시작해요     │  │  ← 선택 카드 (button, name="새 커플 공간 만들기")
│  │ 새 공간을 만들고     │  │
│  │ 짝꿍을 초대해요      │  │
│  └───────────────────┘  │
│  ┌───────────────────┐  │
│  │ 💌 초대 코드를 받았어요│ │  ← 선택 카드 (button, name="초대 코드 입력하기")
│  │ 짝꿍이 보낸 6자리    │  │
│  │ 코드로 합류해요      │  │
│  └───────────────────┘  │
│                         │
└─────────────────────────┘
```

- 두 선택지는 **같은 무게**의 카드다. 한쪽만 primary로 강조하면 초대받은 사람이 습관적으로 "새 공간 만들기"를 눌러 혼자짜리 공간이 하나 더 생긴다.
- 카드는 `OnboardingChoiceCard`(`@uandi/ui`) 프레젠테이션 컴포넌트. 접근성 이름은 기존과 동일하게 유지한다.
- 초대 링크로 들어와 저장된 코드(`uandi:pendingInviteCode`)가 있으면 이 화면을 건너뛰고 **단계 2B를 코드가 채워진 채** 바로 연다.

### 단계 2A — 초대 코드 화면 (공간 생성 직후)

```
┌─────────────────────────┐
│  ← 뒤로                 │
│                         │
│  짝꿍을 초대해요          │
│                         │
│  ┌───────────────────┐  │
│  │    A B 1 2 C D    │  │  ← data-testid="invite-code"
│  └───────────────────┘  │
│  [코드 복사]  [링크 공유] │  ← 공유: navigator.share, 없으면 링크 복사
│                         │
│  코드는 48시간 후 만료돼요 │
│  ◌ 상대가 입력하면 여기서  │
│    바로 알려드릴게요       │
│                         │
│  ┌───────────────────┐  │
│  │   먼저 시작하기     │  │  ← data-testid="start-alone", 새로고침 없이 지난 내역 가져오기로 이동
│  └───────────────────┘  │
│  짝꿍은 나중에 합류해도 돼요│
└─────────────────────────┘
```

- `InviteCodePanel`(`@uandi/ui`) 프레젠테이션 컴포넌트. 대시보드 초대 시트와 공유한다.
- **먼저 시작하기**: `setAuthCookie('with_couple')` + `userAtom.coupleId` 갱신 후 `/inner/cashbook/import?onboarding=1`(지난 내역 가져오기, `pages/inner/cashbook-import.md`)로 이동. 거기서 건너뛰면 대시보드. 서버 라운드트립이나 새로고침이 필요 없다(코드 생성 시점에 이미 `coupleId`가 기록돼 있다).
- **링크 공유**: `${origin}/invite/${code}`. `navigator.share`가 있으면 공유 시트, 없으면 클립보드에 링크를 복사하고 "링크를 복사했어요" 토스트.
- 상대가 합류하면(Firestore 리스너, `memberUids.length === 2`) **단계 3 연결 완료 화면**으로 전환한다. 바로 `/`로 보내지 않는다.

### 단계 2B — 초대 코드 입력

```
┌─────────────────────────┐
│  ← 뒤로                 │
│                         │
│  초대 코드를 입력하세요  │
│                         │
│  ┌───────────────────┐  │
│  │  □ □ □ □ □ □     │  │  ← 6칸 OTP
│  └───────────────────┘  │
│  ✓ 진성님의 초대예요     │  ← 6자리 입력 시 미리보기 (data-testid="invite-hint")
│  [에러 메시지 영역]      │
│                         │
│  ┌───────────────────┐  │
│  │  연결하기          │  │  ← primary, 6자리 입력 시 활성화
│  └───────────────────┘  │
└─────────────────────────┘
```

- 6자리가 모두 입력되면 `previewInviteCode(code)`로 `inviteCodes/{code}`를 1회 `get`해 `createdByName`을 보여준다.
  - 찾음: "OO님의 초대예요" (이름이 없는 구버전 코드면 "초대 코드를 확인했어요")
  - 없음/만료/만석: 미리보기는 숨기고, 연결하기를 눌렀을 때 기존 에러 메시지를 보여준다
- `InviteCodeHint`(`@uandi/ui`) 프레젠테이션 컴포넌트. 상태: `idle | loading | found | unavailable`.
- 초대 링크로 들어온 경우 코드가 채워진 채 열리고 미리보기도 즉시 조회한다. 저장된 코드는 화면을 연 즉시 지운다(한 번만 사용).

### 단계 3 — 연결 완료

```
┌─────────────────────────┐
│                         │
│   [코랄 마스코트][세이지 마스코트]│
│                         │
│   진성님과 연결됐어요!   │  ← data-testid="couple-connected"
│   이제 둘이 함께 가계부를 │
│   채워갈 수 있어요        │
│                         │
│   ┌───────────────────┐ │
│   │     시작하기       │ │  ← data-testid="connected-start" → /inner/cashbook/import?onboarding=1
│   └───────────────────┘ │
└─────────────────────────┘
```

- `CoupleConnectedState`(`@uandi/ui`) 프레젠테이션 컴포넌트. 양쪽(만든 사람·합류한 사람) 모두 이 화면을 거친다.
- 상대 이름은 `users/{partnerUid}`를 읽어 채운다. 합류 직후엔 상대 문서의 `coupleId` 반영이 한 박자 늦을 수 있어 **최대 3회(500ms 간격) 재시도**하고, 그래도 못 읽으면 "짝꿍"으로 표시한다.
- 시작하기: `setAuthCookie('with_couple')` + `userAtom` 갱신 후 지난 내역 가져오기(`/inner/cashbook/import?onboarding=1`)로 이동. 건너뛰면 대시보드.

## 온보딩 투어 (대시보드 첫 진입)

커플 연결 뒤 대시보드에 처음 들어오면 1회 열리는 안내. **기능 카탈로그가 아니라 "첫 행동 안내"** 다.
3장으로 끝나고, 마지막 장이 첫 내역 입력으로 이어진다.

### 노출 시점

- 대시보드가 **한 번 그려진 뒤 약 1.5초 후**에 연다. 연결 완료 화면 → 시작하기 직후 바로 덮지 않고, 커플 카드와 빈 화면을 먼저 보게 한다.
- 열리는 순간에 `localStorage['moa:tour:v1'] = true`를 기록한다(열리기 전에 페이지를 떠나면 다음 진입에 다시 시도).
- 프로필 메뉴 "튜토리얼 다시 보기"로 언제든 다시 연다.
- 올해 목표(예산)가 없으면 대시보드 상단에 **"올해 예산 세우기" 권유 카드**를 보여준다. 위저드로 강제 이동하지 않는다(`pages/02-dashboard.md`).

### 슬라이드 3장

| #   | id              | 제목                      | 설명                                                                                                                                                        | 미리보기                                   |
| --- | --------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 1   | `welcome`       | 둘이 함께 쓰는 가계부예요 | "{짝꿍}님과 같은 가계부를 봐요. 둘 중 누가 적어도 바로 함께 보여요." (짝꿍 이름 없으면 "짝꿍")                                                              | 둘이 가계부 쓰는 마스코트                  |
| 2   | `first-entry`   | 첫 내역을 적어 볼까요?    | "오른쪽 아래 + 버튼을 누르면 돼요. 영수증 사진이나 '점심 만원' 같은 문장만 적어도 자동으로 채워져요."                                                       | + 버튼 모형 + 입력 예시 칩 (스크린샷 아님) |
| 2′  | `entries-ready` | 내역이 들어왔어요         | "가져온 내역은 내역 화면에서 볼 수 있어요. 앞으로는 오른쪽 아래 + 버튼으로 적으면 돼요." (**내역이 이미 있을 때** 2장을 대신한다 — 지난 내역 가져오기 직후) | + 버튼 모형 + 입력 예시 칩                 |
| 3   | `later`         | 예산과 예측은 차차 같이   | "한 해 예산은 곧 같이 세울 거예요. 현금흐름 예측과 점검은 내역이 쌓일수록 정확해져요. 지금은 첫 내역 하나면 충분해요."                                      | 성공 마스코트                              |

- 용어는 **점검** 하나로 통일한다("결산" 금지). 갤러리·재테크·커뮤니티 등 베타 기능은 투어에서 다루지 않는다.
- 실제 화면 스크린샷을 쓰지 않는다. UI가 바뀌어도 어긋나지 않도록 아이콘·마스코트·모형으로만 그린다. (`public/tour/*.webp`와 `screenshots/tour.screenshots.spec.ts`는 폐기)

### 마지막 장 버튼

- **첫 내역 적기** (`data-testid="tour-first-entry"`, primary): 투어를 닫고 `uandi:quick-add` 이벤트를 보내 빠른 추가 시트를 연다.
  - 내역이 이미 있으면(`hasEntries`) 대신 **내역 보기** (`data-testid="tour-view-entries"`) → `/inner/cashbook/history`.
- **둘러볼게요** (`data-testid="tour-start"`, ghost): 투어만 닫는다.
- 대시보드는 `getLatestEntryDate`(1건 조회)로 내역 유무를 알아내 투어 컨텍스트(`hasEntries`)로 넘긴다.
- 1~2장 상단 "건너뛰기"(`tour-skip`)는 유지, 마지막 장에선 숨긴다.

### E2E 시나리오 (`tutorial.spec.ts`)

| 시나리오            | 검증 항목                                                            |
| ------------------- | -------------------------------------------------------------------- |
| 첫 진입             | 대시보드 헤더가 먼저 보이고, 그 뒤 투어가 열린다 (1/3)               |
| 내역이 있는 첫 진입 | 2장이 "내역이 들어왔어요"로 바뀌고 마지막 장 "내역 보기" → 내역 화면 |
| 끝까지 넘기기       | 3/3에서 "첫 내역 적기"·"둘러볼게요" 노출, 건너뛰기 숨김              |
| 첫 내역 적기        | 투어가 닫히고 빠른 추가 시트(`quick-add-sheet`)가 열린다             |
| 둘러볼게요          | 투어만 닫히고 재방문 시 자동 노출 안 됨                              |
| 건너뛰기            | 즉시 닫힘                                                            |
| 다시 보기           | 프로필 메뉴에서 1/3로 다시 열림                                      |

## 기술 명세

### 상태 관리

```ts
type OnboardingStep =
  | 'select' // 초기 선택 화면
  | 'create_pending' // 코드 생성 완료, 상대방 대기 중
  | 'join' // 코드 입력 화면
  | 'connected'; // 연결 완료 (상대 이름 표시 후 시작하기)
```

### 동작 흐름

**새 커플 공간 만들기**

1. `createCouple(uid, displayName)` 호출 → `couples/{id}`(`inviteCode` 포함)·`inviteCodes/{code}`(`createdByName` 포함) 생성
2. 반환된 `coupleId`, `inviteCode`를 화면에 표시
3. `couples/{coupleId}` 실시간 리스너 구독
4. `memberUids.length === 2`가 되면 → `connected` 단계로 전환(상대 이름 조회)
5. 먼저 시작하기 → 리스너 해제 후 지난 내역 가져오기로 이동 (대시보드 초대 카드가 이어받는다)

**초대 코드 입력**

1. 6자리 입력 완료 시 `previewInviteCode` 호출 → 힌트 표시, "연결하기" 활성화
2. `joinCoupleByInviteCode(uid, code)` 호출
3. 성공 → `connected` 단계 (상대 = `inviteCode.createdBy`)
4. 실패 → 에러 유형별 메시지 표시

**초대 링크 `/invite/[code]`**

1. 코드 형식(`[A-Z0-9]{6}`, 대소문자 무시)이 아니면 `/`로 이동
2. `localStorage['uandi:pendingInviteCode'] = code` 저장
3. 인증 상태별 이동: 비로그인 → `/`, 커플 없음 → `/onboarding`, 커플 있음 → `/`(저장값 삭제)

### 에러 메시지

| 에러           | 표시 메시지                                                  |
| -------------- | ------------------------------------------------------------ |
| 코드 없음      | "존재하지 않는 초대 코드예요"                                |
| 코드 만료      | "초대 코드가 만료됐어요. 상대방에게 새 코드를 요청해 주세요" |
| 이미 2명       | "이미 연결된 커플이에요"                                     |
| 자기 자신 코드 | "내가 만든 코드예요. 상대방에게 공유해 주세요"               |

### OTP 입력 컴포넌트

shadcn의 `input-otp` 컴포넌트를 사용한다 (`InputOTP`, `InputOTPGroup`, `InputOTPSlot`). 자동 포커스 이동·붙여넣기 분배는 shadcn이 처리한다.

### 프레젠테이션 컴포넌트 (`packages/ui/src/custom/onboarding/`)

| 컴포넌트               | Props                                                                              |
| ---------------------- | ---------------------------------------------------------------------------------- |
| `OnboardingChoiceCard` | `icon`, `title`, `description`, `onClick`, `ariaLabel`                             |
| `InviteCodePanel`      | `code`, `onCopy`, `copied`, `onShare`, `onStart?`, `expiresLabel`, `waitingLabel?` |

## E2E 테스트 시나리오

| 시나리오                               | 검증 항목                                                                       |
| -------------------------------------- | ------------------------------------------------------------------------------- |
| 선택 화면                              | 두 선택 카드와 각 설명이 표시된다                                               |
| 공간 만들기 → 먼저 시작하기            | 새로고침 없이 지난 내역 가져오기로 이동, 건너뛰면 대시보드에 초대 카드가 보인다 |
| 공간 만들기 → 링크 공유(공유 API 없음) | 클립보드에 `/invite/{code}` 링크가 복사된다                                     |
| 공간 만들기 → 상대 합류                | 연결 완료 화면에 상대 이름이 보이고, 시작하기로 지난 내역 가져오기에 간다       |
| 코드 입력 6자리                        | 초대한 사람 이름 힌트가 표시된다                                                |
| 유효한 코드 → 연결하기                 | 연결 완료 화면 → 시작하기 → 지난 내역 가져오기                                  |
| `/invite/{code}` → 로그인              | 코드가 채워진 입력 화면이 바로 열리고 힌트가 보인다                             |
| 에러 4종                               | 기존과 동일                                                                     |
