# 페이지 명세: 앱 설치 안내 (/get-app) & 앱 전용 게이트

## 목적

말랑 가계부는 **앱(WebView)에서만** 쓴다. 일반 브라우저로 들어온 요청은 로그인 화면 대신
앱 설치 안내로 보낸다.

브라우저에서 로그인하면 Firebase 토큰이 그 브라우저의 IndexedDB에 남는다. 공용 PC, 브라우저
확장 프로그램, 남의 기기처럼 우리가 통제할 수 없는 곳에 토큰이 남는 일을 줄이려는 것이다.

> **이 게이트는 접근 제어가 아니다.** UA와 쿠키는 누구나 위조할 수 있다. 데이터 보호는 여전히
> Firestore 규칙과 API의 ID 토큰 검증이 맡는다. 게이트는 "평범한 사용자가 브라우저에 토큰을
> 남기지 않게" 하는 장치다. 위조까지 막으려면 App Check가 필요하다(이 문서 범위 밖).

## 게이트 동작 (`middleware.ts` + `src/lib/app-gate.ts`)

```
요청
 ├─ 어드민 도메인 ───────────────────────→ 기존 어드민 처리 (게이트 없음)
 ├─ 면제 경로 ───────────────────────────→ 통과
 ├─ 앱 요청 (아래 신호 중 하나) ──────────→ 통과 → 기존 인증 라우팅
 └─ 그 외(일반 브라우저) ────────────────→ 307 /get-app?next={원래 경로}
```

### 앱 요청으로 보는 신호

| 신호                  | 누가 넣나                                                                   | 비고                                                     |
| --------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------- |
| UA에 `UANDI-App` 포함 | 네이티브(UA에 직접 붙일 때), E2E                                            | 현재 출시된 앱은 붙이지 않는다                           |
| 쿠키 `uandi-app=1`    | 웹이 네이티브 브리지(`__UANDI_NATIVE__` / `ReactNativeWebView`)를 확인한 뒤 | 실사용 경로                                              |
| UA에 Android `; wv)`  | (WebView 기본 UA)                                                           | **`/overlay/*`에서만** 인정. 플로팅 버블은 브리지가 없다 |

iOS 앱은 구글 로그인 차단을 피하려고 일반 Safari UA를 쓰므로 서버에서 UA로 구분할 수 없다.
그래서 쿠키를 쓴다.

- 앱의 **첫 요청**에는 쿠키가 없어 `/get-app`으로 간다. 이 페이지의 인라인 스크립트가 브리지를
  확인하면 쿠키를 심고 `next`로 `location.replace` 한다(하이드레이션 전이라 안내 화면이 비치지 않는다).
- 이후에는 `AppClientCookieSync`(providers)가 페이지를 열 때마다 쿠키를 갱신한다.
- 쿠키가 막힌 환경에서 무한 왕복하지 않도록 10초 안의 재시도는 하지 않는다(안내 화면이 그대로 보인다).
- 앱 업데이트 없이 동작한다. 출시된 구버전 앱도 같은 경로를 탄다.

### 면제 경로 (브라우저에서도 열림)

| 경로                                                | 이유                                                  |
| --------------------------------------------------- | ----------------------------------------------------- |
| `/get-app`                                          | 안내 페이지 자신                                      |
| `/privacy`, `/support`, `/account-deletion`         | 스토어 등록정보가 가리키는 공개 URL                   |
| `/admin`                                            | 운영자가 브라우저로 쓰는 화면(전용 도메인이 없을 때)  |
| `/__/*`                                             | Firebase Auth 핸들러 프록시                           |
| 확장자가 있는 정적 파일, `/api/*`, `/.well-known/*` | 페이지가 아니다 (`/api`는 각 라우트가 ID 토큰을 검증) |

### 켜고 끄기

| 환경                                 | 기본값                                 |
| ------------------------------------ | -------------------------------------- |
| 프로덕션 빌드(`NODE_ENV=production`) | 켜짐                                   |
| 로컬 개발(`next dev`)                | 꺼짐                                   |
| E2E(Playwright)                      | 켜짐 — 모든 테스트가 앱 표식 UA로 돈다 |

환경변수 `APP_ONLY_GATE=on|off`로 덮어쓴다. Vercel 프리뷰를 브라우저로 확인하려면 프리뷰 환경에
`APP_ONLY_GATE=off`를 넣는다.

## UI 구성 (`/get-app`)

```
┌─────────────────────────┐
│ ┌─────────────────────┐ │
│ │ 💌 초대 링크로 들어왔어요 │ │  ← next가 /invite/* 일 때만 (data-testid="app-install-invite-hint")
│ │ 앱을 설치한 뒤 받은 초대 │ │
│ │ 링크를 다시 누르면 …    │ │
│ └─────────────────────┘ │
│   [마스코트 일러스트]     │
│                         │
│   말랑 가계부는          │
│   앱에서 만나요          │
│                         │
│   둘의 가계부를 안전하게  │
│   지키기 위해 웹 브라우저 │
│   에서는 로그인할 수 없어요│
│                         │
│  ┌───────────────────┐  │
│  │ Google Play에서 받기│  │  ← data-testid="play-store-link"
│  └───────────────────┘  │
│  ┌───────────────────┐  │
│  │ App Store에서 받기 │  │  ← data-testid="app-store-link"
│  └───────────────────┘  │
│  개인정보처리방침 · 고객 지원 │
└─────────────────────────┘
```

- 프레젠테이션은 `AppInstallLanding`(`apps/web/src/components/landing/`)이 담당한다.
- 로그인 버튼은 없다.
- 스토어 링크는 `src/constants/store-links.ts`.

### 남아 있던 브라우저 세션 정리

게이트가 생기기 전에 브라우저로 로그인한 사용자는 토큰이 이미 저장돼 있다. `/get-app`은
앱이 아닌 환경에서 Firebase 세션이 살아 있으면 **로그아웃**해 저장된 토큰을 지운다
(`BrowserSessionCleanup`).

## E2E 테스트 시나리오 (`e2e/specs/app-gate.spec.ts`)

| 시나리오                                                    | 검증 항목                                              |
| ----------------------------------------------------------- | ------------------------------------------------------ |
| 브라우저로 `/` 접근                                         | `/get-app`으로 이동, 스토어 링크 2개, 로그인 버튼 없음 |
| 브라우저로 `/inner/cashbook`·`/onboarding`·`/settings` 접근 | `/get-app?next=…`으로 이동                             |
| 브라우저로 `/invite/{code}` 접근                            | 설치 후 링크를 다시 누르라는 안내 표시                 |
| 브라우저로 공개 페이지 접근                                 | 그대로 열림                                            |
| 정적 파일 요청                                              | 리다이렉트 없음                                        |
| 로그인된 브라우저가 `/get-app` 도착                         | 세션이 지워지고 `uandi-auth` 쿠키가 없다               |
| 앱 표식 UA로 `/` 접근                                       | 기존 랜딩(로그인) 표시                                 |
| 표식 UA 없이 브리지만 있는 앱                               | 쿠키를 심고 원래 경로로 복귀, 이후 안내를 거치지 않음  |
| 플로팅 버블(wv UA)                                          | `/overlay/*`만 통과                                    |
